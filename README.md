# 📋 Java Kanban

Учебный Java-проект менеджера задач с поддержкой **обычных задач**, **эпиков** и **подзадач**. Приложение умеет:

- хранить задачи в памяти;
- сохранять состояние в CSV-файл и восстанавливать его после перезапуска;
- вести историю просмотров без дубликатов;
- сортировать задачи по времени начала;
- запрещать пересечение задач по времени;
- предоставлять HTTP API для работы с задачами.

Проект реализован без Spring и тяжёлых фреймворков: в основе лежат `Java 21`, встроенный `HttpServer`, собственные менеджеры задач и сериализация JSON через `Gson`.

## Возможности

### 1. Управление задачами
Поддерживаются три типа сущностей:

- `Task` — обычная задача;
- `Epic` — крупная задача, объединяющая подзадачи;
- `Subtask` — подзадача, привязанная к эпику.

Для каждого типа доступны операции:

- создание;
- обновление;
- получение по `id`;
- получение списка всех сущностей;
- удаление по `id`;
- полная очистка коллекции.

### 2. Автоматический расчёт статуса эпика
Статус эпика вычисляется автоматически на основе статусов его подзадач:

- если подзадач нет — `NEW`;
- если все подзадачи `NEW` — `NEW`;
- если все подзадачи `DONE` — `DONE`;
- в остальных случаях — `IN_PROGRESS`.

### 3. Работа со временем и приоритетами
Каждая задача и подзадача может содержать:

- `startTime` — дату и время начала;
- `duration` — продолжительность;
- `endTime` — вычисляется автоматически как `startTime + duration`.

Дополнительно реализовано:

- хранение приоритетного списка задач через `TreeSet`;
- сортировка по времени начала;
- защита от пересечения задач по времени;
- вычисление для эпика:
    - `startTime` — самая ранняя дата среди подзадач;
    - `endTime` — самая поздняя дата завершения;
    - `duration` — суммарная длительность всех подзадач.

### 4. История просмотров
История просмотров реализована через собственную двусвязную структуру и `HashMap`, что позволяет:

- хранить порядок просмотров;
- не допускать дубликатов;
- удалять задачи из истории за `O(1)` по `id`.

### 5. Сохранение в файл
Класс `FileBackedTaskManager` расширяет `InMemoryTaskManager` и автоматически сохраняет данные в CSV после любых изменений:

- создания;
- обновления;
- удаления;
- чтения по `id` (чтобы сохранить историю просмотров).

Из CSV восстанавливаются:

- задачи;
- эпики;
- подзадачи;
- история просмотров;
- следующий `id` для новых сущностей.

### 6. HTTP API
Проект включает встроенный HTTP-сервер `HttpTaskServer`, который запускается на порту `8080` и предоставляет REST-подобные endpoint'ы для работы с задачами и служебными списками.

## Как устроено хранение данных

По умолчанию `Managers.getDefault()` создаёт:

- `FileBackedTaskManager`
- с файлом `resources/data.csv`

Кроме этого, в репозитории есть примеры файлов:

- `tasks.csv`
- `tasks_backup.csv`
- `resources/data.csv`

### Формат CSV
Заголовок файла:

```csv
id,type,name,status,description,epic,startTime,duration,endTime
```

После списка сущностей идёт пустая строка, а затем строка истории просмотров в виде списка `id` через запятую.

## HTTP API

Сервер поднимается на:

```text
http://localhost:8080
```

### Tasks

#### Получить все задачи
```http
GET /tasks
```

#### Получить задачу по id
```http
GET /tasks?id=1
```

#### Создать задачу
```http
POST /tasks
Content-Type: application/json
```

Пример тела:

```json
{
  "name": "Погладить кота",
  "description": "Сделать кота счастливым",
  "status": "NEW",
  "startTime": "2025-07-16T10:00:00",
  "duration": 1800000000000
}
```

#### Обновить задачу
Для обновления нужно передать существующий `id` в теле JSON.

```http
POST /tasks
```

#### Удалить задачу по id
```http
DELETE /tasks?id=1
```

#### Удалить все задачи
```http
DELETE /tasks
```

## Коды ответов HTTP

В обработчиках используются следующие статусы:

- `200 OK` — успешное чтение;
- `201 Created` — успешное создание, обновление или удаление;
- `404 Not Found` — сущность не найдена;
- `406 Not Acceptable` — конфликт по времени (пересечение задач);
- `500 Internal Server Error` — прочие ошибки выполнения.

## Локальный запуск

В проекте **нет Maven или Gradle-сборки** — это Java-проект, ориентированный на запуск из IDE (например, IntelliJ IDEA) или через `javac/java` при наличии зависимостей.

### Вариант 1. Запуск из IntelliJ IDEA

1. Откройте проект.
2. Убедитесь, что выбран **JDK 21**.
3. Подключите библиотеку **Gson**.
4. Запустите:
    - `src/Main.java` — демонстрация файлового менеджера;
    - `src/http/HttpTaskServer.java` — HTTP API сервер.

### Вариант 2. Запуск из командной строки
Понадобится JDK 21 и jar-файл `gson` в classpath.

Пример общей идеи запуска:

```bash
javac -cp gson-2.10.1.jar -d out $(find src -name "*.java")
java -cp "out:gson-2.10.1.jar" http.HttpTaskServer
```

> Для Windows разделитель classpath нужно заменить с `:` на `;`.

После запуска сервер будет доступен по адресу:

```text
http://localhost:8080
```

## Особенности реализации

### Приоритет задач
Приоритетный список задач хранится в `TreeSet<Task>` с сортировкой по:

1. `startTime`
2. `id`

Задачи без `startTime` попадают в конец списка.

### Защита от пересечений
Перед созданием или обновлением задачи выполняется проверка пересечения интервалов времени. При конфликте выбрасывается `IntersectionException`, а HTTP API отвечает кодом `406`.

### История без дубликатов
История реализована не через обычный `List`, а через комбинацию:

- двусвязного списка;
- `Map<Integer, Node>`.

Это позволяет:

- быстро добавлять просмотренную задачу в конец;
- удалять её старую позицию;
- убирать записи из истории при удалении задач.

### Восстановление из файла
`FileBackedTaskManager.loadFromFile(File file)`:

- читает CSV;
- восстанавливает задачи и эпики;
- связывает подзадачи с эпиками;
- пересчитывает статусы и временные поля эпиков;
- восстанавливает историю;
- корректно продолжает генерацию `id`.

## Ограничения проекта

С учётом текущей реализации:

- отсутствует полноценная build-система (`Maven` / `Gradle`);
- отсутствует база данных — используется CSV-хранение;
- HTTP API построен на встроенном `HttpServer`, без Spring MVC;
- сериализация `Duration` и `LocalDateTime` зависит от кастомных адаптеров Gson;
